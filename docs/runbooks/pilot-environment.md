# Pilot environment (UAE North)

AIV-P1-096. The pilot is the dev template (`infra/main.bicep`) with [`infra/pilot.bicepparam`](../../infra/pilot.bicepparam), deployed into its own resource group in UAE North. It holds real candidate data, so AGENTS.md 1.10 applies in full: no shared Medvya resource, no AI inference outside the region, no cross-region replication, malware scanning on. Every step below is the owner's (CLAUDE.md rule 7): agents never apply infrastructure, write Key Vault or change Entra.

## Before the first apply

1. **AI in region.** On 19 Nov 2026 UAE North offered gpt-4.1-mini only as Global Standard (ADR-011). Check `az cognitiveservices model list -l uaenorth` for gpt-4.1-mini with the `Standard` SKU, with quota for 150k tokens a minute (`gpt-main` 100k and `gpt-judge` 50k, both gpt-4.1-mini). Without it the apply stops at `gpt-main`, and the web app and worker are not created. Do not switch the pilot to Global Standard: choose Provisioned, another model offered regionally, or a new ADR (launch epic AIV-P5-E03, #34).
2. **Open shortcuts to close before real candidate data** (each is a `shortcut:` in `infra/modules/`): the Defender verdicts on the worker's copies into `cvs` and `evidence`, and an alert on the 50 GB scan cap (`storage.bicep`); the scan topic's access keys (`storage.bicep`); Service Bus Basic with no duplicate detection, and the relay's namespace-wide send role (`messaging.bicep`); the Key Vault public endpoint (`foundation.bicep`); the Azure-managed email domain (`communication.bicep`); Azure OpenAI abuse-monitoring retention (ADR-011). Production WAF, backups and the restore test: AIV-P5-010.

## Owner steps, in order

Sign in with MFA (`az login`, then `az account set -s <subscription>`).

1. **Resource group and providers**, once:

   ```sh
   az group create -n rg-credalent-pilot -l uaenorth --tags product=credalent env=pilot data=personal
   for p in Microsoft.App Microsoft.DBforPostgreSQL Microsoft.Network Microsoft.OperationalInsights Microsoft.Insights \
     Microsoft.KeyVault Microsoft.ManagedIdentity Microsoft.CognitiveServices Microsoft.ServiceBus Microsoft.Communication \
     Microsoft.EventGrid Microsoft.Storage Microsoft.Security; do az provider register -n "$p" --wait; done
   ```

2. **Entra External ID.** Create the pilot's tenant (or decide to reuse dev's, which then holds real recruiters) and its recruiter app registration and user flow as in [recruiter sign-in](recruiter-sign-in.md). The redirect URI `https://ca-credalent-web-pilot.<environment default domain>/api/auth/callback/entra` is known after step 4; add it then. Note the tenant subdomain, tenant id and client id; they go in the shell, not in a file.
3. **Images.** Pick a commit on `main` that `deploy-dev` has shipped (its images are on ghcr.io); its SHA is `IMAGE_TAG`.
4. **First apply.** It creates the Key Vault, identities, network, database server and AI resource, then stops at the web app because the vault has no secrets yet:

   ```sh
   export IMAGE_TAG=<sha> ALERT_EMAIL=<team address> ENTRA_TENANT_SUBDOMAIN=<subdomain> \
     ENTRA_TENANT_ID=<tenant id> ENTRA_RECRUITER_CLIENT_ID=<client id>
   az deployment group what-if -g rg-credalent-pilot -n credalent-pilot --mode Incremental -p infra/pilot.bicepparam
   az deployment group create  -g rg-credalent-pilot -n credalent-pilot --mode Incremental -p infra/pilot.bicepparam
   ```

   Check the what-if: every location is `uaenorth` or `global` (ACS, with data location UAE; alerts; the private DNS zone).

5. **Key Vault access.** Give yourself Key Vault Secrets Officer on `kv-credalent-pilot-<5 chars>` (the vault uses RBAC).
6. **Secrets.** Write each one with `az keyvault secret set --vault-name kv-credalent-pilot-<5 chars> --name <name> --value …`, never through a file that is tracked:
   - `entra-recruiter-client-secret`: the recruiter app's client secret from step 2 (note its expiry).
   - `auth-secret`: `openssl rand -base64 32`.
   - `acs-webhook-key`: `openssl rand -hex 32`.
   - `notifications-encryption-key`: `openssl rand -base64 32` (base64, 32 bytes).
   - `platform-operator-emails`: the operators' emails, comma-separated ([operator console](operator-console.md)).
   - Later, only with the matching parameter: `entra-candidate-client-secret` (`entraCandidateClientId`) and `google-client-secret` (`googleClientId`).
7. **Second apply**: the same `create` command. It finishes the web app, worker, email, storage and malware scanning. Then add the redirect URI from step 2 (`webFqdn` output).
8. **PostgreSQL Entra admin.** Add yourself: `az postgres flexible-server microsoft-entra-admin create -g rg-credalent-pilot -s <postgresServerName output> -i <your object id> -u <your sign-in name> -t User`.
9. **Database roles and pgvector:** `sh infra/scripts/bootstrap-db.sh rg-credalent-pilot pilot <postgresServerName output>`. Expect `rolsuper`, `rolbypassrls` and `rolcreaterole` false for all four roles.
10. **GitHub environment `pilot`** (Settings, Environments): required reviewer the owner, deployment branches `main` only, and the variables `AZURE_CLIENT_ID` (`cicdIdentityClientId` output), `AZURE_TENANT_ID` and `AZURE_SUBSCRIPTION_ID`. The federated credential `github-pilot` (subject `…:environment:pilot`) is created by the apply; nothing to add in Entra for it.
11. **First migration and deploy:** `gh workflow run deploy-pilot --ref main`, then approve it on the run page. It checks that the commit's `pr` run is green and its images exist, migrates as `aivera_migrator`, deploys web and worker, smoke-tests the public URL, and rolls both back on failure or cancellation. Migrations stay expand-only, as for dev.

## Later deploys

Run `deploy-dev` for the commit first (it builds the images), then `deploy-pilot` from `main` and approve. Re-apply the Bicep only when `infra/` changes, with `IMAGE_TAG` set to the commit running now (`az containerapp show -g rg-credalent-pilot -n ca-credalent-web-pilot --query 'properties.template.containers[0].image' -o tsv`), so the apply moves nothing.
