## Claude-specific rules

1. **Ponytail is mandatory: invoke `ponytail:ponytail` (level `full`) before writing any code**: writing, fixing, refactoring, reviewing and choosing dependencies. No code is written outside it. The plugin is enabled for this repository in `.claude/settings.json`; if it is missing, install it (`/plugin marketplace add DietrichGebert/ponytail`, then enable `ponytail@ponytail`) before coding.
2. **Every PR gets the `code-reviewer` agent** (`.claude/agents/code-reviewer.md`) before it moves to "In review" and after each push that changes code; Copilot reviews automatically too (AGENTS.md 7.0). Resolve every finding before asking for a merge. For a quick self-check use `ponytail:ponytail-review`. For a whole-repo pass, use `ponytail:ponytail-audit`. To list recorded shortcuts, use `ponytail:ponytail-debt`.
3. To write or split tickets, use the `ticket-writer` agent (`.claude/agents/ticket-writer.md`). Every ticket has Gherkin acceptance criteria.
4. End every development reply with one or two lines saying what was skipped or not checked, and any risk the user must know.
5. **Pushing and merging.** Keep work local until the branch is rebased on current `main` and lint, typecheck, unit, integration, the affected Playwright specs and `pnpm build` for touched apps pass (AGENTS.md 5); then push. Agents get a PR green and report; they merge only on the owner's explicit word. Auto-merge is off for this repository (`gh pr merge --auto` errors): watch CI, then run `gh pr merge <n> --squash` for a single PR or `gh stack merge <pr> --squash` for a stack (never `--admin`). Before merging, update the branch onto `main` (`gh pr update-branch <n>`) if `main` moved since the PR's last green run. Never merge red or unfinished CI. When `main` is red, fixing it comes before any other merge. Dependent tickets are stacked PRs (AGENTS.md 7.1); run `gh stack view` before starting work to see open stacks. **After a merge:** `deploy-dev` is manual and runs only on the owner's word ("merge when green and deploy"): once `main`'s `pr` run for the merge commit is green, `gh workflow run deploy-dev --ref main`, then confirm its smoke-test step (`/api/ready` on the public URL) passed. When the merge touched the `ai-eval` workflow's push paths (`packages/ai`, `apps/backend/ai-service`, the AI Bicep), comment the post-merge `ai-eval-live` run on the issue. Close the issue only when every scenario passes, and set the board. An issue with unmet scenarios stays open with a comment listing them.
6. **Ticket status is the Project 2 board Status field** (Todo → In progress → In review → Done): update it when work starts, when the PR is up, and when it merges; close the issue when every scenario passes (rule 5) and the epic when its last ticket is Done (`sh tools/board/status.sh Done <issue>`). Labels are secondary. UI is verified by Playwright tests in CI, not by hand-driving a browser (AGENTS.md 2.8).
7. Local notes: Node 24 LTS (`.nvmrc`), pnpm 11; setup and known test quirks in `docs/runbooks/local-development.md`. Run pnpm as `corepack pnpm` (a bare pnpm 10 on PATH rewrites `pnpm-lock.yaml`) with `CI=true` exported (otherwise scripts wait on a TTY prompt). Docker is Docker Desktop (Testcontainers needs nothing) or Colima (integration tests need `DOCKER_HOST=unix://$HOME/.colima/default/docker.sock TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`); check `docker context ls`. pnpm enforces a minimum release age: pin a version old enough rather than adding `minimumReleaseAgeExclude`. Shell is zsh: `status` is a read-only variable, macOS `sed -i ''`, a tool call that starts with `sleep` is blocked (wait with a background `until` loop). macOS blocks agents from `~/Downloads`: ask the owner to put files under the repository's parent folder instead. Infrastructure applies, Key Vault writes, Entra tenant settings and anything named prod are the owner's. The GitHub API limit (5,000 an hour) is shared by every agent on the account: poll `gh pr checks` or `gh run list` every 2 minutes or more, from one loop at a time.
