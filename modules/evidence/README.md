# @credalent/evidence

Everything a score can rest on (AIV-P1-024): where a piece of evidence came from, the exact excerpt it cites, its provenance, its strength and what it does not show. Other code imports only `@credalent/evidence` (the `EvidenceContract` types); apps build it with `createEvidence(workspaces, now)` from `@credalent/evidence/composition`.

- **Tables:** `evidence.source` (candidate id, kind `cv | repository | document | shipped_product | reference_call | portal_submission | interview_note`, label, https url or blob file id, `captured_at`, `checked_at` and `check_method` such as "Commit history", `synthetic`), `evidence.item` (source, candidate, excerpt, excerpt span such as "page 2", provenance, strength, `limit_statement`, `synthetic`), `evidence.competency_link` (item, job id, competency id of the jobs module, and the `level` 0–5 the item shows for that competency, 0 until mapped) and `evidence.outbox`. Candidate, job and competency ids are opaque: no foreign key across modules. The foreign key `(workspace_id, source_id, candidate_id)` keeps an item on its own workspace's and candidate's source. Migrations are tracked in `migrations.evidence`.
- **Provenance and strength** are closed lists, with the values `ProvenanceTag` and `StrengthMeter` of `@credalent/ui` take: provenance `corroborated | submitted | claim | contradictory | awaiting-defence`, strength `strong | medium | supporting | claim` (the Rubric page's scoring definitions). Labels: `evidence.provenance.*` and `rubric.strength.*` in `packages/i18n`.
- **Invariants:** a `claim` or `awaiting-defence` item is never stronger than Supporting ("A claim cannot be stronger than Supporting"), and every item states its limit ("State what this evidence does not show"). The domain (`checkItem`) refuses both before anything is written, and check constraints refuse them again for any write path. "Claim only" counting zero is scoring's rule (AIV-P1-030).
- **Contract:** `recordEvidence(ctx, { candidateId, source, items, synthetic })` stores a source, its items and their competency links; `linkToCompetency(ctx, itemId, { jobId, competencyId, level })` adds a link once, at the latest level ("A level is a whole number from 0 to 5"); `listEvidenceForCandidate(ctx, candidateId, jobId)` returns the candidate's items with their source and their links to that job (an empty list when there are none); `getEvidenceItem(ctx, id)`; `purgeSyntheticEvidence(ctx)` for the demo seed's reset.
- **Authorisation:** through the workspaces `authorize`: recording and linking as `candidate.create`, reading as `candidate.view` with no job, so admins and recruiters only until applications give a job to check (AIV-P1-017).
- **Row-level security (ADR-005):** every table `ENABLE` + `FORCE ROW LEVEL SECURITY` with `tenantPolicy` on `workspace_id`; the repository also filters by workspace.
- **Event:** `EvidenceRecorded.v1` (the ticket's "evidence.recorded"; `{ candidateId, sourceId, itemIds }`, strict, opaque ids only) is written to `evidence.outbox` in the transaction that records the evidence; the relay sends it to the `assessment` queue.
- **Personal data (AGENTS.md 1.2):** labels, urls, excerpts and limits are candidate personal data (`PERSONAL_DATA_FIELDS`). The module never logs; `EvidenceError` never repeats the refused value.
- **Not here:** CV parsing (AIV-P1-025), GitHub reading (AIV-P1-026), documents and links (AIV-P1-028), mapping evidence to competencies with AI (AIV-P1-027), corroboration rules (AIV-P1-029), scoring (`@credalent/assessment`, AIV-P1-030).
- **Tests:** invariants in `src/domain/evidence.test.ts`; database scenarios in `tests/integration/src/evidence.test.ts`.
