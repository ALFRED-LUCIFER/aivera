# @credalent/candidates

One person per workspace, however many jobs they apply to (AIV-P1-016). The person record holds identity and contact facts only; scores stay with each job's rubric. Other code imports only `@credalent/candidates` (the `CandidatesContract` types); apps build it with `createCandidates(workspaces, now, merging)` from `@credalent/candidates/composition`, where `merging` wires the audit log and intake's and evidence's records for duplicate merge (AIV-P1-018); without it nothing merges and the merge calls throw.

- **Tables:** `candidates.outbox` (events, `outboxTable` from `@credalent/db`), `candidates.person` (display name, emails, phones, location, `synthetic`, `merged_into_id`, `created_at` from the injected clock) and `candidates.person_identifier` (type `email | phone | cv_hash | github_login`, normalised value, person id). The primary key `(workspace_id, type, value)` makes an identifier unique per workspace; the same email in another workspace is another person. The foreign key `(workspace_id, person_id)` keeps an identifier on its own workspace's person. Migrations are tracked in `migrations.candidates`.
- **Contract:** `findOrCreatePerson(ctx, { displayName, identifiers, location, synthetic })`, `getPerson(ctx, id)`, `listPeople(ctx)`. Each takes the request context from `WorkspacesContract.withWorkspace` and runs in its scoped transaction. `findOrCreatePerson` normalises the identifiers (email and GitHub login lower case, phone to E.164, CV hash lower-case hex) and returns the person holding any of them, or creates one holding all. A known person who arrives with a new identifier keeps it, unless another person already holds it; when the identifiers match several people, the earliest is returned and every other one that is an exact duplicate is merged into it (below). Two requests creating the same person at once get one person: the insert runs in a savepoint and, if the identifier was taken meanwhile, the lookup runs again.
- **Authorisation:** through the workspaces `authorize`. `candidate.create` and `candidate.view` (no job) allow admins and recruiters; hiring owners and interviewers are refused until they can reach a person through an application's job (AIV-P1-017).
- **Names read for intake:** `displayNamesInWorkspace(tx, workspaceId, personIds)` from the composition is not authorised itself and is not on the contract: apps wire it into `createIntake` only, whose `listApplicationsForJob` authorises the job and passes that job's applicants alone (AIV-P1-086).
- **Row-level security (ADR-005):** both tables `ENABLE` + `FORCE ROW LEVEL SECURITY` with `tenantPolicy` on `workspace_id`; the repository also filters by workspace.
- **Synthetic:** `synthetic` has no column default and is required in the input, so every seed and import states it (AGENTS.md 1.1).
- **Personal data (AGENTS.md 1.2):** names, emails, phones, location and identifier values are personal data. `PERSONAL_DATA_FIELDS` lists the contract's fields for the telemetry scrubber (AIV-P0-018). The module never logs; `CandidateError` never repeats the refused value, and database errors are redacted by `@credalent/db`.
- **Event:** `PersonCreated.v1` (`{ personId }`, a strict zod schema in the contract, so personal data is refused) is written to `candidates.outbox` in the transaction that creates the person, and the relay sends it to the `candidates` queue (AIV-P0-014). A rolled-back create writes nothing.
- **Duplicates (AIV-P1-018):** match rules are pure in `src/domain/duplicates.ts`. Exact: an arrival holding another record's email, phone or CV hash, or its GitHub login with the same name (`nameKey`: accents, case, spaces and punctuation dropped, so "Omar Al Suwaidi" = "Omar Alsuwaidi"); merged automatically in `findOrCreatePerson`, audited as the system ("merged automatically: same CV file"). Likely: the same name, or an email or phone on both records (a CV address is unverified, AIV-P1-025, so it never merges on its own). `detectDuplicates(ctx, personIds)` returns, per person, the earlier unmerged people of the workspace likely to be them and the merges into them not undone (`candidate.duplicates`: admins and recruiters). `previewMerge`, `mergePeople(ctx, survivorId, mergedId, reason)` (`candidate.merge`: admins and recruiters; interviewers and hiring owners get `ForbiddenError`) and `unmergePeople(ctx, mergeId, reason)` (`candidate.unmerge`: admins, before `undo_until`, set from the workspace's `mergeUndoDays` when merged). A merge moves applications and evidence by intake's `applicationRecords` and evidence's `createEvidenceRecords` (nothing deleted), sets `merged_into_id`, stores what moved on `candidates.merge` (`moved` jsonb, opaque ids), and audits `candidate.merged` last; the undo moves back exactly those and audits `candidate.unmerged`. An automatic merge needs the arrival to be exactly both people: when the earliest match is only a GitHub login under another name, nothing merges. Two arrivals bridging the same pair at once merge it once: the second finds the pair merged after the lock and skips it. **Audit order exception (AGENTS.md 3.6):** an automatic merge runs inside `findOrCreatePerson`, so its `candidate.merged` entry is the last statement of the merge but not of the caller's transaction: intake's `receiveApplication` then writes the application, its source and `ApplicationReceived.v1`. It is safe because it is one transaction: if any later write fails, the merge and its audit entry roll back together, and a committed entry always has its merge. `candidates.merge` has `ENABLE` + `FORCE ROW LEVEL SECURITY`, one active merge per merged person (partial unique index), and survivor and merged foreign keys that include the workspace.
- **Not here:** the people page (AIV-P1-048); dismissing a likely duplicate as "not the same person" (`shortcut:` in `application/merge.ts`), so an undone automatic merge also merges again when a later arrival bridges the pair (`shortcut:` in `application/people.ts`).
- **Tests:** normalisation in `src/domain/person.test.ts`, match rules in `src/domain/duplicates.test.ts`; database scenarios in `tests/integration/src/candidates.test.ts` and `tests/integration/src/duplicates.test.ts`.
